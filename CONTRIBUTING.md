# Contributing to Altium Developer projects

Thanks for your interest! These guidelines apply to every repository in the [AltiumDeveloper](https://github.com/AltiumDeveloper) organization, unless a repository has its own `CONTRIBUTING.md`.

## Ways to contribute

- **Report a problem in something published here.** Open an issue in the repository concerned: a docs page, an API reference, a sample, a template or a library.
- **Report an API, SDK or MCP server problem, or ask for a new capability.** Post it on the [Altium Developer forum](https://forum.live.altium.com/#/forums/100271). For capability requests (new fields, queries, mutations, commands or tools), say which use case it would unlock. See [SUPPORT](SUPPORT.md).
- **Improve docs and samples.** Typo fixes and clearer examples are always welcome, and small PRs are fine without an issue first.
- **Contribute code.** For anything non-trivial, please open an issue first so we can agree on the approach before you invest time.

## Pull requests

1. Fork the repository and create a branch from the default branch.
2. Keep each change focused, one topic per PR.
3. Follow the existing code style and run the repository's build, lint and tests locally.
4. Update docs and changelogs where relevant.
5. Describe what the change does and why, and link the related issue.

A maintainer will review your PR. Some repositories are generated from internal sources (for example API references), so we may implement your change upstream instead of merging the PR directly. You'll still get the credit.

## Licensing

By contributing, you agree that your contribution is licensed under the license of the repository you contribute to (MIT for most repositories here).

## Code of conduct

Everyone taking part is expected to follow our [Code of Conduct](CODE_OF_CONDUCT.md).
